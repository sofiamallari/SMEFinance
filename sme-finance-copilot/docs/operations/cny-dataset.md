# CNY dataset and initialization

Active default: shenzhen_cny_demo. All six merchants use canonical CNY; display is ¥ with CNY/RMB clarification. Fresh RMB budgets are generated by business scale with deterministic seed offset 20261015, not FX conversion or relabeling of old amounts. Merchant IDs/names and nonmonetary scenario patterns remain; seed history ends 2026-09-30. See [six scenarios](../hackathon/scenarios.md).

| Active file | Purpose |
|---|---|
| logs/shenzhen_cny_demo/identity.sqlite3 | Identity, roles/grants, consent, import lifecycle, payment state, drafts, applications and reviews |
| logs/shenzhen_cny_demo/transactions.jsonl | Canonical journal; do not replace independently of its database |
| logs/shenzhen_cny_demo/audit.jsonl / execution.jsonl | Current process-segment financial execution evidence |
| logs/shenzhen_cny_demo/dataset.json | Initialized dataset marker/version, fixed seed date and category counts |

`python -m copilot.cny_demo seed` requires a strong private seed password and an empty target for first initialization; it uses the packaged sanitized manifest. `verify` checks existing data. Idempotent repeat seed does not add duplicates or reset existing passwords. It refuses to auto-replay partial initialization. [Setup instructions](local-setup.md) distinguish a source-only ZIP from an initialized private handoff.

Historical original SQLite/journal/audit/execution and retired generated POS examples remain privately under logs/backups, not as a second active environment. Root legacy default files were retired together after verified backup. Do not publish those backups or copy their passwords/tokens into a new seed. Source templates/test literals retained for historical compatibility cannot make normal server startup silently reseed IDR.

Opening wallets are synthetic assumptions. CNY zero cart tax is a sandbox assumption, not Chinese VAT. Seed assessment scores and reports are recomputed from new data; no maturity stage or eligibility is guaranteed. Demo applications/reviews/payments are synthetic. Scope/authorization rules remain unchanged. Current rolling Survival coverage can age out; do not silently shift dates or regenerate an existing user dataset.
