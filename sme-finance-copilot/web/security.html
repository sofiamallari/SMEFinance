AI & MCP Controls

AI safety tiers

T0 Read · T1 Advise · T2 Sandbox Write · T3 Owner approval required · T4 Permanently prohibited

Tier ceilings can only stay within or reduce each role's fixed maximum. Financial actions still require their action permission, merchant scope and consent.

MCP authentication requirements

MCP callers require a server-authenticated session. Cookie writes require CSRF protection; Bearer sessions carry the same identity, membership and consent checks.

Environment-selected demo roles and API keys do not establish identity under the four-role baseline. Tokens and keys are never displayed or exported here. These requirements are read-only.

Immutable AI restrictions

The AI cannot approve actual credit, disburse real funds, change real limits, bypass owner approval or consent, access unrelated merchants, elevate permissions, modify security settings or create privileged accounts.

Bank Authorization Policies

Existing enforcement · read-only

SME Owners authorize and revoke individual Bank access through /consents. Each grant includes a purpose, data categories and expiration.

Banks need scoped membership, enabled financial/action permissions and current Owner authorization for each data category. General merchant reads do not require case assignment; submitted packets remain restricted to their routed Bank. Revoked or expired authorization blocks subsequent access.

The recipient is an individual account; its organization records affiliation. These consent rules are not global configurable settings. Individual grants, recipient identities and local consent records never enter a portable configuration file.
